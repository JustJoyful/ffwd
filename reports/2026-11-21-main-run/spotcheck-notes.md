## INCIDENT: the main run died at step 38 of 60 (21 Nov 2026, about 22:20 IST, after 6h 48m); last clean checkpoint: checkpoint-30
* **What:** `torch.OutOfMemoryError: CUDA out of memory ... 14.27 GiB is allocated by PyTorch, and 55.76 MiB is reserved but unallocated` (so a real allocation, not fragmentation; `expandable_segments` was on), exit code 1. The traceback is in the GENERATION path (`training_step -> _generate -> rollout_func -> ... hf_batch generate`), 38 steps done, steps 31 to 37 trained normally (loss 0.10 to 0.26, reward 0.79 to 1.02, step time 429 to 1,030 s, longest completion 1,176 tokens, none clipped). Steps 31 to 38 are lost (about 1.4 GPU-h); the Hub holds checkpoint-10, 20 and 30.
* **Cause (mine, two parts):** (1) I raised the generation chunk from 8 to 16 for speed (unverified); a long-prompt batch then needed more memory than the T4 has. (2) The split-and-retry I had added after the control's OOM retried INSIDE the `except` block, where the exception's traceback keeps the failed attempt's frames, and the CUDA tensors they hold, alive: every retry started with the failed batch's memory still allocated and failed again down to one sequence. The retry therefore never worked.
* **Fix:** the retry now runs after the handler exits, with `gc.collect()` + `torch.cuda.empty_cache()` before it and before every generation call (`training/grpo/hf_batch.py`). A test pins the condition (`sys.exc_info()` is empty during a retry); the old code fails it. The chunk stays at 16 (a failing chunk now splits 16 -> 8 + 8, the size the control ran at).
* **Why I did not notice for about two hours:** my watcher only waited for the next checkpoint to appear, so a dead run looked the same as a slow one, and the Kaggle status I could read describes API-started runs, not web-UI sessions. The watcher now also fires if no new checkpoint appears within a stall limit. I should have built that before saying nothing needed the owner.
* **Resume:** kernel version 13 (main, `--resume`) restores checkpoint-30 from the Hub and continues to step 60.
